# A shallow dive into Reinforcement Learning
Reinforcement learning is a huge field, and I’m still finding my way through it—but I find it especially interesting because it feels quite different from most of the machine learning I have seen before. In this post, I’m going to cover the **classical foundations** and the **thinking behind them**—the core definitions and equations that most methods build on, and the main “families” of approaches people use in practice. In this blog my goal is to give a big-picture map of RL.

Before we get into it, I want to acknowledge a resource that influenced how I think about RL: Lilian Weng’s blog post, “*A (Long) Peek into Reinforcement Learning*” (2018). It’s exceptionally clear and thorough, and if you want to go deeper than this “shallow dive” 🤿, I genuinely recommend reading it (and her other posts too).

So what is reinforcement learning, in plain terms? The way I think about it is: instead of learning from a static dataset like in supervised learning, RL is about learning by doing. You have an agent that interacts with an environment—it takes an action, gets some feedback (a reward), and sees how the world changes.
And this is exactly why RL sits nicely in the broader ML toolbox. If supervised learning is mostly about prediction and pattern recognition, RL is about decision-making over time. It shows up naturally in settings like games, robotics, and other control problems.

## Markov Decision Processes (MDPs)

To talk about reinforcement learning precisely, we usually wrap the problem in a Markov Decision Process (MDP). The reason is simple: it gives us a clean mathematical model for “an agent repeatedly makes decisions, the world responds, and rewards show up along the way.”

An MDP is typically written as:

$$
(\mathcal{S}, \mathcal{A}, P, R, \gamma)
$$

- $\mathcal{S}$: the set of states
- $\mathcal{A}$: the set of actions
- $P(s_{\text{next}} \mid s,a)$: transition dynamics (probability of landing in the next state)
- $R(s,a)$: the reward function
- $\gamma \in [0,1)$: the discount factor (how much we care about future rewards)

### The Markov assumption

The key assumption is the Markov property: once you know the current state, the future doesn’t depend on the full history.

$$
P(s_{t+1}\mid s_t, a_t, s_{t-1}, a_{t-1}, \ldots) = P(s_{t+1}\mid s_t, a_t)
$$

Informally: the current state $s_t$ is a sufficient summary of the past.


## Policies: how the agent behaves

A policy is just the agent’s behavior rule. It tells you what action to take in each state.

- Deterministic: $\pi(s) = a$
- Stochastic: $\pi(a \mid s)$ (a distribution over actions)

When we say “the agent is learning,” we usually mean it’s improving its policy.


## Returns and value functions

To define “better,” we need a notion of long-term reward. Starting at time $t$, the return is:

$$
G_t = r_t + \gamma r_{t+1} + \gamma^2 r_{t+2} + \cdots
$$

Now we can define value functions, which measure how good states (or state-action pairs) are under a policy.

### State-value function

$$
V^\pi(s) = \mathbb{E}_\pi\left[ G_t \mid s_t = s \right]
$$

Interpretation: if I start in state $s$ and follow policy $\pi$, what return should I expect?

### Action-value function

$$
Q^\pi(s,a) = \mathbb{E}_\pi\left[ G_t \mid s_t = s, a_t = a \right]
$$

Interpretation: if I start in $s$, take action $a$ now, and then follow $\pi$, what return should I expect?


## The Bellman equation (the core idea)

The value of a state can be written recursively: it’s the immediate reward plus the discounted value of the next state (in expectation). This is the Bellman expectation equation for $V^\pi$:

$$
V^\pi(s)
=
\sum_{a \in \mathcal{A}} \pi(a \mid s)
\sum_{s_{\text{next}} \in \mathcal{S}} P(s_{\text{next}} \mid s,a)
\left( R(s,a,s_{\text{next}}) + \gamma V^\pi(s_{\text{next}}) \right)
$$

If we want the best possible behavior, we define the **optimal** value functions:

$$
V^*(s) = \max_\pi V^\pi(s)
\qquad
\text{and}
\qquad
Q^*(s,a) = \max_\pi Q^\pi(s,a)
$$

They satisfy the **Bellman optimality equations**:

$$
V^*(s) = \max_{a \in \mathcal{A}}
\sum_{s_{\text{next}} \in \mathcal{S}} P(s_{\text{next}} \mid s,a)
\left(R(s,a,s_{\text{next}}) + \gamma V^*(s_{\text{next}})\right)
$$

$$
Q^*(s,a) =
\sum_{s_{\text{next}} \in \mathcal{S}} P(s_{\text{next}} \mid s,a)
\left(R(s,a,s_{\text{next}}) + \gamma \max_{a' \in \mathcal{A}} Q^*(s_{\text{next}},a')\right)
$$


## how RL algorithms differ

At a high level, most RL methods are trying to answer the same question: *how do I choose actions to maximize long-term reward?* The differences mostly come from what information we assume we have access to, and what we’re trying to learn.

A useful first split is:

- Do we know the environment dynamics? i.e., do we know $P(s_{\text{next}} \mid s,a)$ and $R(s,a)$?
- If not, can we still learn purely from experience?

There’s one more distinction that we will discuss when we go through the TD learning methods below!


### 1) Dynamic Programming (Known model)

If we know the environment model (the transition probabilities and reward function), then we can **plan** directly. In that setting we don’t have to “guess” what happens after an action—we can compute the expectation exactly using $P(s_{\text{next}} \mid s,a)$ and $R(s,a)$.

DP methods are built straight from the Bellman equations and work by repeatedly applying **Bellman backups** until the values (and policy) stabilize.

At a high level, there are two classic DP algorithms:

#### Policy Iteration 

Policy iteration the idea is simple if I can evaluate a policy, I can make it better by acting greedily with respect to its value function.

It repeats two steps:

**1) Policy evaluation**: given a fixed policy $\pi$, compute $V^\pi$. The Bellman equation is:

$$
V^\pi(s)
=
\sum_{a \in \mathcal{A}} \pi(a \mid s)
\sum_{s_{\text{next}} \in \mathcal{S}} P(s_{\text{next}} \mid s,a)
\left( R(s,a,s_{\text{next}}) + \gamma V^\pi(s_{\text{next}}) \right)
$$

In practice, we approximate this by iterating until the value function stops changing much (because solving it exactly can be expensive but can be solved as linear equations).

**2) Policy improvement**: update the policy to be greedy with respect to the current values:

$$
\pi_{\text{new}}(s) =
\arg\max_{a \in \mathcal{A}}
\sum_{s_{\text{next}} \in \mathcal{S}} P(s_{\text{next}} \mid s,a)
\left( R(s,a,s_{\text{next}}) + \gamma V^\pi(s_{\text{next}}) \right)
$$

#### Value Iteration

In the value iteration we computes the optimal value function directly, without explicitly keeping a separate “current policy” during learning. Instead of evaluating a fixed policy $\pi$, it repeatedly applies the Bellman optimality backup to push $V$ toward $V^*$.

The key update is:

$$
V(s) \leftarrow
\max_{a \in \mathcal{A}}
\sum_{s_{\text{next}} \in \mathcal{S}} P(s_{\text{next}} \mid s,a)
\left( R(s,a,s_{\text{next}}) + \gamma V(s_{\text{next}}) \right)
$$

Here’s the intuition I like to keep in mind: for each state $s$, value iteration looks one step ahead, it considers every possible action, averages over the possible next states using the known transition model, and picks the action that gives the best “immediate reward + discounted future value.” Repeating this update over and over makes the value function converge.
Once $V$ is close to $V^*$, we can recover an optimal policy by acting greedily with respect to the learned values:

$$
\pi^*(s) =
\arg\max_{a \in \mathcal{A}}
\sum_{s_{\text{next}} \in \mathcal{S}} P(s_{\text{next}} \mid s,a)
\left( R(s,a,s_{\text{next}}) + \gamma V(s_{\text{next}}) \right)
$$

Compared to policy iteration, value iteration usually does *less work per iteration* (since there’s no full policy evaluation loop), but it may need more iterations overall. Conceptually, both are just different ways of applying Bellman backups until things stabilize. The key difference I had to remember—since this is what confused me at first—is that in policy iteration the value function is explicitly the value of the current policy, $V^\pi$, whereas in value iteration we update values directly toward $V^*$ without committing to evaluating any particular policy along the way (we can extract a greedy policy when we want, typically at the end).

### 2) Monte Carlo methods

Once we drop the “known model” assumption, we can’t compute Bellman expectations exactly because we don’t know $P(s_{\text{next}} \mid s,a)$. A simple idea is that we don’t model the environment at all just run a policy, collect complete episodes, and average what actually happened.
so if I visit a state $s$ many times while following a policy $\pi$, I can estimate its value by averaging the returns I observe after visiting it:

$$
V^\pi(s) \approx \frac{1}{N(s)} \sum_{i=1}^{N(s)} G^{(i)}(s)
$$

Here:
- $G^{(i)}(s)$ is the return observed after the $i$-th visit to $s$ (in some episode),
- $N(s)$ is the number of times we’ve visited $s$.

Similarly, for action-values:

$$
Q^\pi(s,a) \approx \frac{1}{N(s,a)} \sum_{i=1}^{N(s,a)} G^{(i)}(s,a)
$$

For an episode, the return from time $t$ is:

$$
G_t = r_t + \gamma r_{t+1} + \gamma^2 r_{t+2} + \cdots
$$

Monte Carlo methods wait until the episode finishes so they can compute these returns exactly from the sampled rewards.

There are two common variants:

- **First-visit MC**: only update from the first time a state appears in an episode.
- **Every-visit MC**: update from every occurrence of the state within the episode.

To move from *evaluating* a fixed policy to actually finding an **optimal policy**, Monte Carlo methods can be used in a control loop:

1) generate episodes using an exploratory policy (often $\epsilon$-greedy, meaning we choose the current best action with probability $1-\epsilon$ and a random action with probability $\epsilon$),  
2) estimate $Q(s,a)$ from the observed returns,  
3) update the policy to be greedier with respect to the new $Q$ estimates.

This should feel very similar to the Policy Iteration story from above DP section, Policy iteration alternates between policy evaluation and policy improvement using the known model ($P$ and $R$). MC control follows the same high-level template, except the “evaluation” step is done from sampled episodes, so we can improve policies even when the dynamics are unknown.

### 3) Temporal-Difference (TD) learning

Monte Carlo methods are simple and model-free, but they come with a practical drawback: to compute returns $G_t$, you usually have to wait until the episode ends. For long episodes (or environments that don’t really end), this become a big problem.
Temporal-Difference (TD) learning keeps the model-free setup, but updates online using a one-step lookahead. The core idea is to update value estimates using a **bootstrap target** (bootstrapping means we build the update target using an existing estimate like $V(s_{t+1})$ or $Q(s_{t+1},a)$, so we can learn without needing to see the entire future trajectory which is what we do in MC we saw above):


$$
\text{target} = r_t + \gamma V(s_{t+1})
$$

So the TD update for a state-value function looks like:

$$
V(s_t) \leftarrow V(s_t) + \alpha \left( r_t + \gamma V(s_{t+1}) - V(s_t) \right)
$$

The term inside parentheses is the **TD error**:

$$
\delta_t = r_t + \gamma V(s_{t+1}) - V(s_t)
$$

For control, it’s often more convenient to learn an action-value function $Q(s,a)$ directly, because then we can act greedily:

$$
\pi(s) = \arg\max_{a \in \mathcal{A}} Q(s,a)
$$

Earlier I mentioned there’s another distinction that becomes important once we start learning from experience. This is that split:

- **On-policy** methods learn about the same policy they use to generate data.  
  In other words, the agent is learning the value of the behavior it is actually following (including any exploration it’s doing).

- **Off-policy** methods learn about a different target policy while collecting data using a separate behavior policy (often more exploratory).  
  The intuition I like is: you can behave one way to gather experience (explore), but learn about another policy in the background (the greedy/optimal one).

With that in mind, **SARSA** is the classic on-policy TD control method, while **Q-learning** is the classic off-policy one.


#### SARSA (on-policy)

SARSA learns the value of the policy it is actually following. The name comes from the tuple it uses in the update:
$(s_t, a_t, r_t, s_{t+1}, a_{t+1})$.

The SARSA update is:

$$
Q(s_t,a_t) \leftarrow Q(s_t,a_t) + \alpha \left( r_t + \gamma Q(s_{t+1},a_{t+1}) - Q(s_t,a_t) \right)
$$

Key idea: the bootstrapped term uses $Q(s_{t+1}, a_{t+1})$, where $a_{t+1}$ is sampled from the same behavior policy (often $\epsilon$-greedy). So SARSA learns the value of behaving with exploration included.


#### Q-learning (off-policy)

Q-learning learns the greedy optimal action-value function, even if the data was collected using an exploratory behavior policy.

Its update is:

$$
Q(s_t,a_t) \leftarrow Q(s_t,a_t) + \alpha \left( r_t + \gamma \max_{a' \in \mathcal{A}} Q(s_{t+1},a') - Q(s_t,a_t) \right)
$$

Key idea: instead of using the next action actually taken, Q-learning uses the best next action according to the current $Q$ estimate. That $\max$ is what makes it off-policy it learns about the greedy target policy regardless of how the experience was generated.
